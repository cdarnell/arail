## Summary
ARAIL's agent execution plane is a set of independent asyncio/thread background loops (Buddy, SRE, Presence, Librarian) plus an on-demand Researcher and a request-driven Browser/Drafter, all wired to the `/agents` "Agent Control Center" tab. The scaffolding is thoughtfully built — failsoft watchers, per-key cooldowns, crash-resume checkpoints, a genuinely educational planning-trace disclosure, and a clean host-seam abstraction. But the two things a non-expert most needs — *trustworthy, clearly-labeled output* and *no surprising network egress* — are where it breaks down. The Researcher's "experiments" are pure theater: timed `asyncio.sleep` loops that emit LLM-hallucinated (or hardcoded) metrics which are then written into the Knowledge Base and the final report **with no "simulated/model-generated" label**. Meanwhile the documented per-domain egress-consent flow is effectively decorative: the Browser agent and Buddy reach the live internet in hybrid mode without ever consulting the ConsentStore, and Buddy even puts the user's private goal text into a HuggingFace URL query. The "swarm" is a single agent with decorative dashboard lanes. Airgapped-default behavior is safe; almost all the risk surfaces the moment a user flips to hybrid.

## Current state

**Invocation / lifecycle.** `agents/loader.py` discovers `lab/pkb/agents/<id>/AGENT.md`, dynamically imports `<id>.py`, and caches a singleton (`loader.py:181-269`), falling back to `_builtin_<id>` for shipped agents (`loader.py:62,166-178`). `start_all_auto` reads `auto_start_env`/`dream:` frontmatter and calls `.start()` (`loader.py:272-317`). Portal startup installs the egress guard, loads all agents, and starts them (`portal/app.py:750,1003-1010`, dream daemon `:1020`). Auto-started loops: Buddy (`LAB_BUDDY`), SRE (`LAB_SRE`), Presence (`LAB_PRESENCE_AGENT`), Librarian (`LAB_LIBRARIAN`) per `builtin_seed.py:48,624,777,854`. The Researcher does **not** auto-start — it launches only when a goal is submitted (`portal/app.py:2746-2748,2843-2846`). Curator and Drafter are not loops (request-driven).

**Buddy** (`_builtin_buddy.py`) is a two-cadence observe-and-speak loop (`:1230-1247`): every ~90s it runs `WATCHERS`, every ~15min (goal-gated) it runs `SUGGESTERS`, picks one Observation, paraphrases it through the local model (`_voice`, `:1093-1105`) and emits one sentence into the activity feed. Prompt assembly layers system persona + world framing + yesterday's dream + skills + the fact (`_compose_prompt`, `:1057-1090`). It nightly writes a "dream" reflection that is auto-indexed into the KB (`:1358-1410`, `write_buddy_dream`). It is **not** a chat agent on the `/agents` tab and cannot be instructed there (the instruct dropdown lists only Researcher and Browser — `agents.html:131-134`).

**SRE** (`_builtin_sre.py`) ticks every ~120s, runs error/crash/service-health/CVE/cleanup watchers, and emits one raw clinical fact at `warn` (`:547-608`). It is observe-only — it never restarts, kills, or remediates anything; every watcher output just points the user at an Admin page (`:335,361,381,444`). Service-health does a localhost GET (`:263-285`).

**Researcher** (`agents/researcher.py`) is the 6-step engine: KB consult → plan hypotheses → design experiments → "gather sources" → **run experiments** → analyze → report (`_run`, `:692-1047`). Persona is intent-driven system context (`:40-162`). It supports pause/resume/halt with on-disk checkpoint recovery (`:517-542,694-718`), redirect steering (`:299-355`, only the Researcher reads redirects — grep confirms `get_agent_redirect` used only in researcher.py), and prompt-trace emission for the Prompt Inspector (`:231-245`).

**Browser** (`agents/browser.py`) shells out to the `agent-browser` CLI to open URLs, screenshot, extract text to the PKB (`browse_url`, `:90-160`; `chat`, `:209-413`). Drafter (`_builtin_drafter.py`) is a solid compose-only persona ("Never invent facts… write `[need: <what>]`", `:39-56`) used by blueprints, not the portal tab.

**Support layer.** `deep_policy.py` centralizes the fast-vs-deep decision and silently falls back to fast on any deep failure/OOM (`:148-190`). `consent.py` is a pending/allowlist/history store (`:28-153`). `dream_daemon.py` polls the heavy window and calls each registered agent's `dream()` (`:146-173`). `forge.py` codegens a voice-only agent, AST-validates, writes the folder, and hot-loads (`:502-570`). `swarm_goals.py` compiles a plain-dict worker/phase plan; the Researcher turns it into a prompt block and decorative workflow lanes (`researcher.py:565-635`).

**UX positives.** The planning-trace disclosure genuinely teaches ("LLM-generated" vs "Heuristic fallback", `research.html:919-920`; `researcher.py:1208-1246`). Watchers are failsoft (`_builtin_buddy.py:1257-1260`). Agent cards show status/tokens/recent actions and link to source + a "📖 Learn" doc (`agents.html:208-225`).

## Gaps

1. **Researcher "experiments" are simulated, and the fabricated results are written to the KB and report with no label.** The run loop just sleeps in `slice_sec` granules to look "alive" (`researcher.py:923-963`), then produces an LLM "observation" (`:1274-1291`) and "analysis." When the model is absent or returns unparseable JSON, the analysis is **hardcoded**: `improvement_rate: 0.15, confidence_score: 0.72, data_points: 24, "Experiment supports the hypothesis with moderate confidence"` (`:1325-1331`). Even the LLM path merely asks the model to invent those numbers with zero grounding (`:1298-1306`). These values are rendered as `## Results` into per-experiment PKB markdown (`_experiment_markdown`, `:1367-1370`) and the heuristic report asserts "All experiments completed with data collection and analysis" (`:1419-1420`). The educational planning-trace only labels the *hypothesis* step (`research.html:919-920`); nothing labels the results/report as simulated. A non-expert cannot distinguish a real finding from a canned template — the opposite of "trustworthy and clearly labeled."

2. **Buddy silently reaches HuggingFace in hybrid mode, bypassing consent and leaking goal text.** `_suggest_internet_correlation` calls `urllib.request.urlopen("https://huggingface.co/api/papers?search=<goal tokens>")` (`_builtin_buddy.py:942-951`), gated *only* by `is_airgapped()` (`:921-923`) — it never touches `ConsentStore`. It runs on every suggest cadence (~15 min) whenever a goal is active. This (a) contradicts the stated model "agents have ZERO network access by default" (`consent.py:1-11`), (b) is a privacy leak — the user's private research goal is placed in a third-party URL query string, and (c) is invisible: Buddy's own airgap message even tells the user consent "still gates browser/curator" (`:539`), implying Buddy is exempt, which no UI discloses.

3. **The Browser agent is not consent-gated at all — only airgap-gated — contradicting its own docstring.** `browser.py:5` claims "consent-gated when hybrid," but `browse_url` (`:96-101`) and `chat` (`:220-225`) only check `_is_airgapped()`; the word "consent" never appears in the file. The `/api/browse` and `/api/browse/chat` endpoints pass straight through (`app.py:9802-9823`), and the `/agents` instruction bar wires a non-expert's free-text instruction directly to `/api/browse/chat` (`agents.html sendInstruction`, "if browser instruction, also trigger a browse chat"). So typing "find papers about X" causes the lab to actually browse model-chosen URLs on the live web in hybrid mode with **no per-domain prompt**.

4. **The per-domain egress-consent flow is decorative end-to-end.** The egress guard's hybrid branch is "pass through" with no consent lookup (`egress.py:291,296`; `airgap.py:148-149` returns `hybrid` while the comment claims "consent layer takes over" — it doesn't). The only code that creates consent requests is the Curator (`curator.py:116-127`), but the Researcher never calls `curator.fetch_approved` (grep: zero callers), and approving a request (`app.py:4083-4090`) triggers no fetch. Net effect: consent neither gates real egress (gaps 2–3) nor does anything on approval — yet the Researcher tells the user "N sources auto-approved / N awaiting your approval" (`researcher.py:907-914`), implying sources are fetched and used. They never are; the report is 100% parametric-knowledge/heuristic.

5. **The "swarm" is one agent with decorative dashboard lanes.** `_swarm_prompt_block` injects worker labels into the single Researcher's prompt (`researcher.py:565-585`) and `_set_swarm_lane_status`/`_sync_swarm_phase` write per-worker workflow snapshots (`:607-680`) that render as separate "swarm lanes," but no worker executes independently — one `ResearcherAgent` makes every LLM call. To a non-expert the dashboard looks like a coordinated multi-agent team when it is a single loop.

6. **Degradation to canned fallbacks is invisible in the delivered artifact.** With no model available, `_get_router` returns None (`researcher.py:165-176`) and every step silently uses heuristics — yet the Researcher still emits a complete report, writes fabricated metrics to the KB, and stamps it "Generated by Arail Researcher Agent" (`:1443`) with no "no model was available / this is a template" marker. The only signal is a transient `warn` in the activity log (`:246-256`). Buddy behaves the same way — `_voice` silently returns the raw watcher fact when the model is down (`_builtin_buddy.py:1097-1105`).

7. **Misleading "70B+" deep-inference message.** `researcher.py:269` hardcodes "Deep inference — 70B+ model from disk, this takes time…", but per `CLAUDE.md` the maximus deep persona is Qwen2.5-7B. The string overstates the model to a non-expert and is not derived from the resolved entry.

8. **Forged agents are silent by default, but Deploy reports success/started.** `forge.py`'s template ships an empty `WATCHERS` list with the comment "Without any watchers, {name} will emit the 'online' message on start and then stay quiet" (`forge.py:276-281`), yet `deploy` returns `started: true` (`:559-570`). A non-expert who forges an agent through the two-panel UI gets an agent that prints one "online" line and then never speaks again, with no UI hint that hand-editing Python is required.

9. **Instructing an idle Researcher looks like a no-op.** `/api/agents/instruct` stores a redirect (`app.py:4328-4352`) that is only consulted at run start / source-gathering (`researcher.py:833,890`). If no run is active, the UI reports "Instruction applied" but nothing observable happens until the user later starts a goal — surprising for the "Tell the agent what to do…" placeholder.

## Quick wins
- **Label simulated output.** Reuse the existing `source: "llm" | "heuristic"` provenance pattern (`research.html:919-920`) on the *results* and *report*: add a banner in `research.html` and a provenance line in `_experiment_markdown`/`_generate_report` (`researcher.py:1367,1443`) stating results are model-generated/simulated, not measured. High trust impact, low effort.
- **Stop the silent egress.** Gate Buddy's HF lookup behind `ConsentStore.is_allowed`/`request_access` (or an explicit "allow paper scans" toggle) and remove the goal text from the URL query (`_builtin_buddy.py:942-951`); route `browse_url`/`chat` through a consent check before egress (`browser.py:96,220`). At minimum, fix the false "consent-gated" docstring (`browser.py:5`).
- **Make consent real or honest.** Either have an approved request trigger `curator.fetch_approved` and feed fetched text into the report, or drop the "N sources auto-approved/awaiting approval" messaging (`researcher.py:900-919`) that implies fetching happens.
- **Fix the "70B+" string** (`researcher.py:269`) to read from the resolved deep entry, or state the actual deep persona name/size.
- **Disclose the swarm is one agent** — a tooltip on the lane cards ("views of a single Researcher run") — or actually parallelize.
- **Forge honesty** — on Deploy, warn "no watchers yet — this agent will stay quiet until you add one," or ship one starter watcher so a forged agent visibly does something (`forge.py:279-281,559-570`).
- **Surface degraded-mode** — when `_get_router()` returns None, stamp the report and KB entries with a visible "generated without a model (template only)" marker rather than only an activity-log warn (`researcher.py:165-176,246-256`).
