## Summary
ARAIL's security model is "loopback is the trust boundary, the operator is the only user" — and the code is honest and largely correct about that: the egress/airgap guard is genuinely fail-closed and airgapped-by-default, and the browser-borne (DNS-rebind + CSRF) defenses are well-built. The problem for the owner's stated goal is the *hand-off* scenario. After first-run onboarding the portal has NO authentication at all: the passphrase gates the code-server IDE, ttyd, and Marimo, but the dashboard itself treats anyone who can open the browser as the owner. That same unauthenticated surface exposes an arbitrary-code-execution plugin installer (git clone + pip install of any repo) that is not even tier-gated, plus notebook/terminal surfaces. Tier is a nav-visibility choice, not an access boundary (only opencode is server-gated). Several secrets (the passphrase in .env/lab.conf/code-server config, and in the Marimo iframe URL) are stored/exposed less carefully than the 0600-hardened secrets.env. The guards are real; the gap is that a non-expert who hands the laptop to a friend gets none of the protection the password prompt implies.

## Current state
DEFAULTS (safe): .env.example sets LAB_TIER=minimalist (.env.example:55), LAB_MODE=airgapped (.env.example:62), BIND_ADDR default 127.0.0.1. lab_mode() collapses anything != "hybrid" to airgapped (src/arail/airgap.py:48-58), is_airgapped() defaults True — fail-closed.

AUTH: There is no authentication layer. The only gate is the `onboarding_gate` middleware (src/arail/portal/app.py:282-329), which calls `_lab_password_set()` (app.py:250-276) — this checks only whether SOME passphrase is configured in env/.env, never whether the incoming request PRESENTED it. Once onboarded, every request passes through with no credential check (grep for session/cookie/Authorization on dashboard routes finds none). The comment "The portal has no auth: loopback is the trust boundary" (app.py:516) is accurate. ARAIL_PASSWORD is used only as (a) the one-time onboarding trigger and (b) a downstream bearer secret: code-server config.yaml password (app.py:1303-1314), ttyd/IDE via lab.conf IDE_PASSWORD (app.py:1275-1300), and Marimo via `?access_token=<ARAIL_PASSWORD>` embedded in the iframe URL (app.py:2195, 2232-2245). Jupyter is launched with an EMPTY token AND empty password (app.py:1884-1885: `--NotebookApp.token= --NotebookApp.password=`).

BROWSER-BORNE DEFENSES (well-built): `local_trust_boundary` middleware (app.py:563-584), registered outermost, enforces a positive Host allowlist via `_host_is_trusted` (app.py:534-560) against DNS rebinding, plus blanket CSRF (Sec-Fetch-Site not cross-site/none AND Origin==Host) on all POST/PUT/PATCH/DELETE. ARAIL_ALLOWED_HOSTS extends it (app.py:549-551); a specific LAN BIND_ADDR auto-allows that IP; a wildcard bind (0.0.0.0/::/empty) DISABLES the Host check entirely (app.py:557-559).

REACHABLE WITH NO PASSWORD: pre-onboarding, only /welcome, /api/welcome/*, /static/, health/metrics, favicon (app.py:304-316); everything else 302→/welcome or 401. Post-onboarding (steady state): EVERY route + every mutating endpoint (airgap toggle, provider save/remove, plugin install, consent approve/revoke, notebook/marimo start) is reachable with no credential; CSRF same-origin is the only barrier, which any real browser user on the host satisfies.

CODE-EXEC SURFACES: POST /api/plugins/install (app.py:4032-4042 → src/arail/plugins/manager.py:45-91) validates only that the URL matches github.com/owner/repo (manager.py:32-34), then runs `git clone --depth 1` (manager.py:62-65) and, if requirements.txt exists, `pip install -r requirements.txt` (manager.py:78-81) — pip executes arbitrary setup/build code as the user = arbitrary local code execution. It has NO tier gate and NO server-side confirmation. Tier is nav-visibility only, not access control: /plugins (app.py:2277), /notebook (app.py:1830), /api/notebook/start (app.py:1852), /marimo (app.py:2227), /api/marimo/start (app.py:2249), /notebooks (app.py:2143) have no server-side tier gate and are reachable by direct URL on a minimalist lab; only opencode is properly gated via `_require_workbench` → 404 (app.py:1918-1928, 1938). ttyd terminal is a MINIMALIST surface (app.py:153); /terminal embeds its iframe (app.py:1822-1827); ttyd + Jupyter (empty token) + code-server are all arbitrary local code execution, loopback-bound by default.

EGRESS/AIRGAP (correct & fail-closed): install_guard() runs FIRST at portal startup (app.py:747-757) and in the agent loader (src/arail/agents/loader.py:254); it monkeypatches requests HTTPAdapter (adapters+sessions), installs a urllib opener, and class-patches httpx transports (src/arail/egress.py:442-485). Decision tree denies airgapped+non-local loudly with EgressBlocked (egress.py:262-289, 298-332). allow_egress() is a hard ratchet: raises immediately in airgapped mode, no escape hatch except BUDDY_EGRESS_PROBE (egress.py:511-560). The probe is opt-in, one raw TCP connect to 1.1.1.1:443, off by default (egress.py:650-693). egress.jsonl is chmod 0640 (egress.py:218-220), airgap_audit.jsonl chmod 0600 (app.py:9370-9383). Documented gaps (airgap.py:11-15, docs/PRIVACY.md): guard does NOT wrap aiohttp, raw sockets, or subprocess shells; and is_local_host trusts the system resolver (DNS-rebind limit, airgap.py:96-113).

CONSENT: ConsentStore persists a per-DOMAIN (netloc) allowlist to allowlist.json with no expiry (src/arail/agents/consent.py:42-60); "remember_domain" adds the whole domain (consent.py:111-112); consent files are plain write_text, no chmod (consent.py:152-153). approve/deny/revoke endpoints (app.py:4083-4111) are unauthenticated beyond onboarding.

SECRETS: Provider tokens (HF_TOKEN, ANTHROPIC_API_KEY, etc.) land in lab/data/secrets.env chmod 0600, git-ignored (app.py:1509-1536, 1592) — good. But the passphrase is written in plaintext with NO chmod in three files by the welcome flow: .env via _write_env_kv (app.py:1246-1272, holding ARAIL_PASSWORD and the identical OPEN_NOTEBOOK_ENCRYPTION_KEY, app.py:1207-1208), lab.conf via _patch_lab_conf_password (app.py:1275-1300), and ~/.config/code-server/config.yaml via _write_code_server_password (app.py:1303-1314). All are git-ignored (.gitignore:2,6). Marimo also embeds the passphrase in the iframe URL query string (app.py:2195, 2232-2245) whereas opencode deliberately avoids credentials-in-URL (app.py:2207, 2217).

ONBOARDING UX: welcome.html lists what the passphrase protects — the :8443 IDE, Open Notebook encryption, "future per-tab guards" (src/arail/portal/templates/welcome.html:188-194) — and truthfully says nothing leaves 127.0.0.1 (welcome.html:182-185). It never states the dashboard has no login. The plugin install UI shows only a "git clone" label + Install button (plugins.html:22-33); the only confirm() is on plugin REMOVE (plugins.html:126). SECURITY.md and docs/PRIVACY.md ("Loopback trust boundary") are candid that the passphrase authenticates the IDE but not the dashboard and that plugins are a bring-your-own-code surface.

## Key files
- src/arail/portal/app.py — Portal core. onboarding_gate (only checks a password EXISTS, not that it was presented) app.py:250-329; 'portal has no auth' + local_trust_boundary CSRF/Host-allowlist middleware app.py:514-584; passphrase written plaintext to .env/lab.conf/code-server app.py:1246-1314; Marimo passphrase-in-URL app.py:2195,2232-2245; unauthenticated, un-tier-gated plugin install route app.py:4032-4042; opencode's _require_workbench (the one real server-side gate) app.py:1918-1928.
- src/arail/plugins/manager.py — Arbitrary code execution surface: install() runs git clone + pip install -r requirements.txt on any github.com/owner/repo (manager.py:45-91). No sandbox, and its only caller has no auth/tier gate.
- src/arail/egress.py — The 700-line egress guard. Confirms fail-closed airgapped default, install_guard monkeypatching of requests/urllib/httpx (442-485), allow_egress hard ratchet (511-560), BUDDY_EGRESS_PROBE opt-in (650-693). Correct — but does not wrap subprocess/aiohttp/raw sockets.
- src/arail/airgap.py — Single source of truth for outbound policy: lab_mode() fail-closed to airgapped (48-58), is_local_host resolver-trust DNS-rebind limit (96-113). Documents the guard's threat model and gaps (11-15).
- src/arail/agents/consent.py — Per-domain web-consent allowlist persisted to allowlist.json with no expiry (42-60, 111-112); plain write_text with no chmod (152-153). Shows how browsing consent persists across runs.
- src/arail/agents/browser.py — browse_url docstring claims 'consent-gated when hybrid' (5,94) but code only checks _is_airgapped() (96-101) then shells out to agent-browser via subprocess (115-133) — bypasses both consent_store and the Python egress guard.
- src/arail/portal/templates/welcome.html — First-run explainer. Lists what the passphrase protects (188-194) but never tells a non-expert the dashboard itself has no login — the key hand-off-scenario gap.
- SECURITY.md — States the threat model candidly: passphrase authenticates the IDE but not the dashboard; plugin install is bring-your-own-code; consent persists across runs — all treated as known trade-offs, not bugs.
- docs/PRIVACY.md — 'Loopback trust boundary' section admits the portal has no auth and anyone on 127.0.0.1:8080 is 'the user'; documents guard gaps (subprocess/raw sockets), BUDDY_EGRESS_PROBE, and shared-machine guidance.
- .env.example — Confirms safe defaults: LAB_TIER=minimalist (55), LAB_MODE=airgapped (62); no ARAIL_PASSWORD pre-seeded; ARAIL_ALLOWED_HOSTS guidance (73-75).

## Gaps
1. No dashboard authentication after onboarding: onboarding_gate only checks that a passphrase EXISTS (src/arail/portal/app.py:300, 250-276), never that the request presented it — so any person who can open the browser on the machine (a friend, kid, housemate) is treated as the owner for EVERY endpoint including the airgap toggle, provider-token save/remove, plugin install, and consent approve. The passphrase gates code-server/ttyd/Marimo but not the dashboard (app.py:516; SECURITY.md; docs/PRIVACY.md 'Loopback trust boundary').
2. Unauthenticated arbitrary code execution via the plugin installer: POST /api/plugins/install (app.py:4032-4042) → git clone + pip install of any GitHub repo (src/arail/plugins/manager.py:62-81). pip runs the repo's build/setup code as the user. No tier gate, no server-side confirmation, and the UI (plugins.html:22-33) warns nothing — the only confirm() is on plugin REMOVE (plugins.html:126). A curious friend pasting a URL gets code execution.
3. Tier is nav-visibility, not an access boundary: /plugins, /notebook, /api/notebook/start, /marimo, /api/marimo/start (app.py:2277,1830,1852,2227,2249) have no server-side tier check and are reachable by direct URL on a minimalist lab; only opencode uses _require_workbench→404 (app.py:1918-1928). A non-expert who stays on minimalist 'for safety' is not actually walled off from those surfaces.
4. Passphrase stored world-readable in plaintext with no chmod in .env (_write_env_kv, app.py:1246-1272), lab.conf (app.py:1275-1300), and ~/.config/code-server/config.yaml (app.py:1303-1314), while secrets.env and audit logs are hardened to 0600 (app.py:1536, 9383; egress.py:220). On a multi-user machine other Unix users can read it; because ARAIL_PASSWORD == OPEN_NOTEBOOK_ENCRYPTION_KEY (app.py:1207-1208) that also leaks the notebook at-rest encryption key.
5. Browser-agent consent drift + guard bypass: browse_url advertises 'consent-gated when hybrid' (browser.py:5,94) but only checks _is_airgapped() (browser.py:96) and then opens ANY url via the agent-browser subprocess (browser.py:115,126,129,133) — which bypasses the Python egress guard entirely (airgap.py:11-15) and never consults consent_store. The per-domain consent the dashboard displays is not enforced for browse_url, and once granted with 'remember' it persists forever (consent.py:111-112).
6. Marimo embeds the passphrase in the iframe URL query string: ?access_token=<ARAIL_PASSWORD> (app.py:2195, 2232-2245). It lands in browser history — so a borrowed/handed-off laptop's history reveals the lab passphrase, which is also the code-server and notebook-encryption secret. opencode explicitly avoids this pattern (app.py:2207,2217).
7. First-run onboarding lacks a hand-off safety explainer: welcome.html lists what the passphrase protects (welcome.html:188-194) but never states 'the dashboard has no login; anyone who can open this browser is treated as you and can run code / toggle egress / read tokens.' A non-expert reasonably assumes the password prompt walls off the whole lab.
8. No warning when the portal is bound off loopback: bind_is_loopback is computed and surfaced only inside /api/airgap status (app.py:9289) and the airgap toggle refuses when non-loopback (app.py:9345-9349), but there is no loud startup/portal banner warning that binding to a LAN IP or 0.0.0.0 exposes the un-authenticated dashboard; a wildcard bind silently disables the Host-allowlist check (app.py:557-559).

## Quick wins
- Add a first-run 'hand-off' safety card to welcome.html (and the dashboard) stating plainly: the dashboard has no login — anyone who can open this browser can run code, flip egress to hybrid, install plugins, and read your API tokens. This closes the biggest expectation gap for the non-expert who hands over the laptop, and it's docs/template-only.
- Gate the state-changing/code-exec routes with the same server-side check opencode already uses (_require_workbench, app.py:1918-1928): /api/plugins/install, /plugins, /api/notebook/start, /api/marimo/start. Add a server-side confirmation flag + a UI warning on install ('this clones and pip-installs arbitrary code as you').
- chmod 0600 the .env, lab.conf, and code-server config.yaml writes (app.py:1246-1314) to match secrets.env (app.py:1536) — a few lines each, removes plaintext-passphrase world-readability.
- Stop embedding ARAIL_PASSWORD in the Marimo iframe URL (app.py:2195,2232-2245); proxy it the way opencode does (env/subprocess, no credentials in URL) so the secret stops leaking into browser history.
- Align browse_url with its documented contract: consult consent_store (and honor per-domain allow/deny) in hybrid mode, or fix the 'consent-gated when hybrid' docstring (browser.py:5,94) so it does not overclaim.
- Emit a loud portal banner + startup log warning when BIND_ADDR is not loopback (the bind_is_loopback signal already exists at app.py:9289) — one visible warning that the un-authenticated dashboard is now reachable beyond 127.0.0.1.
- Consider an optional real auth mode (session cookie keyed to ARAIL_PASSWORD) for users who want to hand the machine to family — even a lightweight, opt-in gate would convert the existing passphrase into actual dashboard protection.
