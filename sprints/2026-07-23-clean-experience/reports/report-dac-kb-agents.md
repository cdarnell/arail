## Summary
ARAIL's knowledge flow is a clean, mostly-honest pipeline: data enters via inbox ingest, portal uploads, and agent writes; lands as raw markdown under lab/pkb/; is vector-indexed into LanceDB (pkb_pages); and is gated at retrieval by a human-approved Compiled-KB manifest before any agent sees it. The gate (compiled_kb.py) is real, fail-closed, and has exactly one write path (the human clicking Promote via /api/pkb/promote), so the core 'agents build only on approved knowledge' invariant genuinely holds for the general KB. The DaC boundary is well-drawn: world_forge.py is a runtime re-export shim over the shared dac_world package, world bundles are sealed/verified/versioned, terms.json is treated as data (never prompted), and world term pages reach agents only as gated candidates. The largest defect is that the entire Tier-2 'user understanding' fact store, described in detail across docs/conversation-memory.md, docs/agents.md, and docs/adr/0002, has ZERO implementation: no fact distillation, no lab/pkb/understanding/ writer, no BuddyHost.recall_user_facts, no quote-sourcing. Only Tier-1 transcripts exist. Secondary gaps: conversation meta.json (user-authored titles) leaks into the searchable index despite the .jsonl guard, ARAIL_CONVERSATIONS_DIR can silently defeat the wipe contract, and turn.progress events are never persisted so crash partial-recovery is aspirational.

## Key files
- src/arail/pkb.py — Core PKB module: ingest (79-164), _PKB_TEXT_SUFFIXES (376), _iter_pkb_files (391-404), index_all (481-533), gated search/search_for_agents (613-672), and all agent write helpers (677-849). Hub of ingest-store-index-consume.
- src/arail/compiled_kb.py — The Compiled-KB gate: approve/reject/revoke, approved_paths (fail-closed), gate_enabled (ARAIL_APPROVED_ONLY), the review queue, and sha256-based drift/version discipline. The single enforcement point behind agents-build-only-on-approved-knowledge.
- src/arail/chat/conversations.py — Tier-1 conversation store: JSONL event log, fold-by-turn_id, terminal events, idempotent orphan sweep. Enforces .jsonl-never-.json (62-63) and PKB-rooted location; the ARAIL_CONVERSATIONS_DIR override (43-48) is the wipe-contract hole.
- src/arail/world_mount.py — DaC bundle host: dual-sha256 seal verification, category gate, mount pointer, is_world_machinery_path (91-103), and _write_term_pages (1124-1192) that lands gated world term candidates. Encodes the terms.json-is-data-never-prompted boundary (14-22).
- src/arail/world_forge.py — The DaC integration seam: a runtime re-export shim over the shared dac_world package. Marks the approved reversal of the no-cross-repo-runtime-imports rule and lists which forge/gate/seal names ARAIL depends on.
- src/arail/lab_brain.py — Chat brain: retrieve_chat_context (501-535) is the gated agent-retrieval path; build_chat_messages/build_chat_payload (604-693) assemble prompts. The documented distilled-fact injection is absent here, which is where it would live.
- docs/conversation-memory.md — The schema contract for chat memory. Accurately describes Tier-1 but specifies a Tier-2 understanding/fact store and recall_user_facts that do not exist in code: the primary docs/code divergence.
- docs/adr/0002-chat-memory-and-the-dac-boundary.md — Authoritative record of the DaC boundary (control plane vs data plane) and the gate invariants it claims ARAIL already runs. Must be superseded before wiring memory to DaC.
- src/arail/pkb_index.py — Incremental LanceDB upsert engine: debounced, non-blocking, path-safe, schema validation and staleness sweep. Governs how raw and agent-written files reach the searchable index.
- src/arail/librarian_scout.py — The declare-gate-version discipline for worlds: drafts term proposals from PKB signals, requires a human click, enforces the closed-sourced-graph gate, keeps model-asserted vs sourced provenance honest.

## Gaps
1. Tier-2 user-understanding fact store is documented as shipped but has ZERO implementation. docs/conversation-memory.md (entire Tier 2 section), docs/agents.md:143-160 (fourth memory tier at lab/pkb/understanding/<fact_id>.md), and docs/adr/0002 describe fact distillation from user quotes, gate_status/fact_id/superseded_by frontmatter, BuddyHost.recall_user_facts, and top-K approved-fact injection in lab_brain.build_chat_messages. Repo-wide greps for understanding/, recall_user_facts, fact_id, gate_status, superseded_by return nothing in src/ or tests/; no lab/pkb/understanding/ dir is created; build_chat_messages (lab_brain.py:604-641) injects gated general-KB RAG via retrieve_chat_context, not distilled facts. The invariants 'agents read only approved distilled facts sourced to verbatim quotes' and 'facts never distilled from agent output' are unbuilt and unenforceable.
2. Conversation meta.json leaks into the searchable index despite the .jsonl guard. conversations/<cid>/meta.json has suffix .json, which is in _PKB_TEXT_SUFFIXES (pkb.py:376) and is not world machinery, so _iter_pkb_files (pkb.py:391-404) indexes it into pkb_pages and the ungated GET /api/pkb/search (app.py:9868-9872) returns it. meta.json holds the user-authored conversation title (chat/conversations.py:73-77), which can be sensitive. The .jsonl invariant protects turn content but its sibling .json metadata is still indexed/searchable. It is not a Compiled-KB candidate (_is_candidate rejects .json) so it stays out of agent retrieval, but is in the raw index and human KB search.
3. ARAIL_CONVERSATIONS_DIR can silently break the wipe-PKB-wipes-memory contract. conversations_root() (chat/conversations.py:43-48) honors ARAIL_CONVERSATIONS_DIR before falling back to PKB_ROOT/conversations. reset.sh reset_pkb() only rm -rf's PKB_DIR (scripts/reset.sh:202); if the override points outside the PKB root, transcripts survive ./arailctl reset pkb, the exact silent privacy break ADR-0002 and docs/agents.md:150-152 warn against. The override is undocumented in the privacy docs.
4. turn.progress events are never persisted, so the documented incremental event model and crash partial-recovery are partly aspirational. The chat stream handler (app.py:6951-6983) writes only turn.started and terminal turn.completed/turn.failed; it accumulates deltas in memory and never appends turn.progress. docs/conversation-memory.md specifies turn.progress carries the incremental slice. sweep_orphans (conversations.py:243-267) recovers a hard-crashed turn with empty partial_text because no progress was logged. The orphan-to-interrupted invariant still holds; partial-text recovery does not.
5. Gate fail-closed means a fresh lab gives non-expert users an empty, ungrounded chat until the owner approves knowledge. With ARAIL_APPROVED_ONLY on (default) and nothing approved, search(approved_only=True) returns [] (pkb.py:637-641), so chat RAG, goal drafter, and Researcher retrieve nothing. By design (escape hatch ARAIL_APPROVED_ONLY=off, compiled_kb.py:383-385) but off by default: friction against the product goal of being inviting for non-expert friends and family, who must first learn the /dac review-and-approve workflow.
6. Human-facing wiki/browse surfaces are ungated while agent retrieval is gated, an intentional but easily-missed asymmetry. wiki.py rebuild (wiki.py:245) indexes all *.md including unapproved agent outputs and raw world term pages; ungated pkb.search backs /api/pkb/search. Agent outputs in agents/research|experiments|synthesis|recommendations and buddy/dreams (pkb.py:677-849) are visible in the human wiki/KB immediately but reach agents only after human promotion. Correct by design, but the wiki graph is not gated the way agent retrieval is.
7. Two independent, slightly divergent path-to-kind classifiers. pkb._source_kind_for_rel (pkb.py:411-426) emits agent_buddy_dream and has no world_term kind (world terms fall through to user); compiled_kb._kind_of (compiled_kb.py:166-181) emits agent_dream and world_term. Same rules, different labels, two sources of truth: cosmetic today but a drift risk if either is used for filtering.
8. ADR-0002 and conversation-memory.md cite mechanisms that do not exist as described. conversation-memory.md's BuddyHost.recall_user_facts and 'Buddy folds the result into _compose_prompt' have no code. ADR-0002 references _builtin_buddy.py:198-201 for the wipe contract; those lines are the _state_file()/state.json comment block (_builtin_buddy.py:185-201) about agent self-memory, accurate for state.json but not fact-recall. The docs read as if the fact loop is live.
