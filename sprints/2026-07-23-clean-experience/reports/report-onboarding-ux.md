## Summary
ARAIL's setup script is genuinely novice-friendly — numbered `1/11` progress banners, idempotent phases, auto-install of Homebrew/Python/Node behind single prompts, auto-bumping of busy ports, and a clear closing banner with the passphrase and next steps (`scripts/setup.sh`). There is also a well-built 3-step browser first-run wizard (`welcome.html`: passphrase → network mode → World) and strong plain-English concept docs (`agents-explained.md`, `missions.md`, `tier-selection.md`). However, the first-run path is undermined by three structural problems: (1) the polished welcome wizard is **skipped** on the primary documented path because a real passphrase captured at the CLI satisfies the onboarding gate, so most users never see the World/mode picker; (2) the "New to ARAIL?" runbook banner sends first-timers straight to `docs/the-lab.md`, which is badly stale (old `min`/`max` tiers, AirLLM 70B/405B, a Qwen3-8B setup that no longer matches reality); and (3) the single most important first action — setting a goal — is labeled four different ways across the setup banner, dashboard, docs, and the actual UI. For a non-expert the biggest intimidation is the **default** first goal: pressing Enter accepts a goal about optimizing AirLLM KV-cache quantization on a 70B Llama, which is both expert-level and about a backend that isn't installed. The pieces of a great onboarding exist but are disconnected and partly stale.

## Current state

**The happy-path setup flow (`./arailctl setup`).** `scripts/setup.sh` runs an 11-phase flow with visible checkpoint banners (`setup.sh:66`, `step()`), all idempotent (`INSTALL.md:118`). It detects platform/accelerator (`setup.sh:167`), auto-installs Homebrew/Python/Node with one confirm each (`setup.sh:250`, `setup.sh:405`, `setup.sh:502`), auto-resolves free ports and pins them in `lab.conf` (`setup.sh:347`), then prompts for: lab name/tagline (`setup.sh:1073`), tier (`setup.sh:1157`), network mode (`setup.sh:1302`), passphrase (`setup.sh:1403`), and intent + first goal + work windows (`setup.sh:1843`). It closes with a friendly banner naming the assistant, the passphrase, and next steps (`setup.sh:2244-2315`). Failure modes are handled softly (setup.log tails on pip failure `setup.sh:157-161`; portable `timeout` shim so model pulls don't fail on stock macOS `setup.sh:649-665`).

**The browser first-run wizard exists but is usually bypassed.** `welcome.html` is a clean, accessible 3-step wizard (passphrase, then network mode, then a World picker that recommends the "AI & Machine Learning" World and highlights the self-explaining "QuKaiZen" World). But it only renders when `_lab_password_set()` is false — i.e. when `ARAIL_PASSWORD` is empty/`change-me`/`__needs_setup__` (`app.py:234`, gate at `app.py:283-329`). The standard interactive `./arailctl setup` captures a **real** passphrase (`setup.sh:1403-1428`), so the gate passes and `/welcome` is never shown (`welcome_page` even redirects home if onboarded, `app.py:1166-1170`). The wizard's mode + **World** steps therefore fire only when `ARAIL_DEFER_PASSWORD=1` (`setup.sh:1353`) or when the user skips CLI setup entirely. CLI setup itself never mounts a World — it only integrity-verifies the shipped bundles (`setup.sh:2176`).

**First portal load.** `/` renders `dashboard.html` (`app.py:1319`). First-run affordances: a dismissible "New to ARAIL? Read the runbook" banner linking to `/docs/the-lab.md` (`dashboard.html:384-393`); a mission-empty card reading "No active mission. Goals are set in the Autoresearch cockpit" with an "Open Autoresearch →" button (`dashboard.html:629-631`); a "Mission docs ↗" help link (`dashboard.html:572`); and two first-start activity-log lines ("Welcome to Arail. Type a goal above to begin…" plus a tip with example goals, `app.py:912-918`). On first start the lab also seeds a "model-building" starter pack of 9 primers into the KB (`app.py:920-935`, `arail.pkb_seed`) and starter skills. Every surface has reassuring empty states (e.g. `dashboard.html:894` "No pending requests. Agents are running locally.", `research.html:145`, `research.html:266-280`).

**The Docs surface.** `docs_registry.py` is a frontmatter-driven catalog over `docs/` + a curated root allowlist, with categories Getting Started → Concepts → Operating → Reference → Design (`docs_registry.py:47-55`), `audience`/`read_minutes`/`related`/`buddy_prompt` metadata, and a denylist that hides internal specs like `maximus.plan.md`, `chat-studio.spec.md` (`docs_registry.py:60-72`). Docs is available on **both** tiers (`_TIER_SURFACES["minimalist"]` includes `docs`, `app.py:124`; `_nav.html:13`).

**Onboarding/tutorial affordances inventory (complete):** the gated `/welcome` wizard; the runbook banner; per-surface empty-state text; the "Mission docs ↗" link; first-start activity-log welcome/tip; starter-pack + skill seeding; and "Ask Buddy about this doc" seed prompts in docs frontmatter (`the-lab.md:20`, `agents-explained.md:14`). There is **no** guided tour / coachmarks / tooltip walkthrough / first-run checklist anywhere in the templates (grep for tour/coachmark/introjs/shepherd finds only incidental link text). This despite `design.md`'s self-description as "progressive disclosure as pedagogy" (`design.md:3`).

**Concept docs quality.** `agents-explained.md` ("An agent is a loop that notices things and speaks up", a traced tick diagram, a hello-world agent) and `missions.md` ("A mission is your goal plus the swarm…", the Draft→Approve flow) are excellent beginner on-ramps. `tier-selection.md` is current and concrete. `the-lab.md` is positioned as *the* 12-minute first read (README top, `README.md:44`) and is category order 0 (top of the Docs hub, `the-lab.md:5`) but is stale (see Gaps).

**The fork/rename story.** `examples/peanut_farmer/` — cited by CLAUDE.md as "the canonical PeanutLab example of forking + renaming" (`CLAUDE.md:140`) — is a single `run.py` offline goal→experiment demo with **no README** and no fork/rename content (`examples/peanut_farmer/run.py`). Rebrand-in-one-line is explained well in prose (`README.md:269-280`, `INSTALL.md:378-389`, `BLUEPRINTS.md:52-58`) but the named worked example doesn't demonstrate it.

## Gaps

1. **The guided first-run wizard is dead on the main path.** `welcome.html`'s mode + World picker only appears when the passphrase is unset/deferred (`app.py:283-300`, `_PASSWORD_PLACEHOLDERS` `app.py:234`), but interactive `./arailctl setup` always captures a real passphrase (`setup.sh:1403-1428`) and never mounts a World (`setup.sh:2172-2183`). Result: the majority path lands straight on the dashboard with no World chosen and never sees the one screen designed to say "here's what your lab is about." README calls Worlds "**Start here**… the main surfaces" (`README.md:136-138`), yet nothing in the default flow starts the user there.

2. **The "read this first" runbook is stale and will mislead a novice.** The dashboard's first-run banner links to `docs/the-lab.md` (`dashboard.html:385`), which still describes `min`/`max` tiers, **AirLLM 70B/405B**, a "~5 GB for Qwen3-8B" starter download, and a 10-step setup with a differently-ordered passphrase step (`the-lab.md:74-119`, `the-lab.md:335-340`). A friend/family user following it will look for tiers, models, and steps that no longer exist. It is also order 0 (top of the Docs hub).

3. **The first action ("set a goal") has four conflicting names.** The setup banner says click **"Run Research"** (`setup.sh:2262`) and CLAUDE.md echoes it (`CLAUDE.md:262`); the first-start activity tip says "Type a goal **above**" (`app.py:914`); the dashboard says "Goals are set in the Autoresearch cockpit → **Open Autoresearch**" (`dashboard.html:630-631`); the actual Autoresearch UI has **"Set Research Goal"** → **"Review Swarm"** → **"Approve & Run"** (`research.html:278`, `research.html:319`, `research.html:88`) plus a separate **"▶ Run"** (`research.html:56`); and `missions.md` calls the first button **"Draft Swarm Plan"** (`missions.md:16,32`), which does not exist in the template. No "Run Research" button exists anywhere. A non-expert following the instructions will hunt for a control that isn't there.

4. **The default first research goal is expert-hostile.** For the default intent (`ai`, chosen by pressing Enter), pressing Enter again accepts the "signature" goal: *"Optimize AirLLM's tokens-per-second when streaming a 70B Llama from disk… sweep KV-cache quantization and prefill chunk size…"* (`setup.sh:1900-1919`). This is the opposite of inviting for "friends, family, and the curious," and it targets AirLLM, which is opt-in and not installed by default (`setup.sh:589-603`). The friendly example goals ("grow peanuts in zone 7", "learn Rust") appear only as non-default hints (`app.py:917`, `research.html:308`).

5. **README/CLAUDE.md say Docs is maximus-only; the product ships it on both tiers.** `README.md:242` ("📖 Docs *(max)*") and `CLAUDE.md:121` ("max adds Admin and Docs") contradict `_TIER_SURFACES["minimalist"] = {… "docs"}` (`app.py:124`) and the nav (`_nav.html:13`). A minimalist user is told the learning surface is locked when it isn't (INSTALL.md gets this right, `INSTALL.md:67`).

6. **"Only one model, no bloat" conflicts with what setup actually downloads.** README states `llama-ai-eng` (~0.9 GB) "is the only model that ships pre-installed" (`README.md:91`) and the banner reinforces "~0.9 GB" (`setup.sh:2256`). But on Apple Silicon `download_model` still snapshot-downloads **Qwen3-8B-4bit (~5 GB)** unconditionally (`setup.sh:1744-1751`) and writes `MODEL_NAME=Qwen3-8B` into `.env` (`setup.sh:1447`), while `llama-ai-eng` is a separate Ollama model the banner tells the user to "pick in the Chat tab" (`setup.sh:2257`). So a minimalist first-timer pulls ~5.9 GB, and it's unclear which model "My Machine" chat uses out of the box — a direct threat to a visible win in the first 5 minutes.

7. **Stale troubleshooting entry for the default model.** `TROUBLESHOOTING.md:159-167` ("`ollama pull qwen3:8b` is taking forever … ~5 GB") references a model the default setup no longer pulls; there is no entry for the real default (`ollama pull llama3.2:1b` / `ollama create llama-ai-eng`) failing.

8. **No progressive-disclosure/tour affordance in the portal.** Despite `design.md:3` claiming "progressive disclosure as pedagogy," there is no tour, no coachmarks, no first-run checklist, and no contextual tooltips introducing surfaces. Onboarding is a dismissible banner (→ stale doc) plus empty-state text. A non-expert must self-navigate five-plus surfaces with no guided "do this first, then this."

9. **The named "fork story" doesn't tell the story.** `examples/peanut_farmer/run.py` is an offline goal→experiment script with no README and no forking/renaming demonstration, yet it's cited as the canonical fork+rename example (`CLAUDE.md:140`) and PeanutLab is the running rename example in README/the-lab (`README.md:22`, `the-lab.md:76`). There's no end-to-end "here's how gentoofoo turned this into PeanutLab" walkthrough for a beginner.

10. **Seeded sample content is AI-centric regardless of chosen intent.** The starter pack seeds "model-building" primers into the KB on first start (`app.py:920-923`) even when the user chose `farming`, `culinary`, `health`, etc. as their intent (`setup.sh:1846-1869`). A gardening-lab owner opening the Knowledge Base to 9 AI-model-building documents is confusing and off-theme.

11. **First prompts assume infra vocabulary.** The passphrase step (CLI `setup.sh:1403-1411` and `welcome.html:188-195`) frames the secret around "code-server IDE", "Open Notebook at-rest encryption", and "future auth proxy" — terms a non-expert friend won't recognize, presented before any payoff. The researcher also auto-starts on its own after a 5-minute courtesy delay (`app.py:900-905`, `MACOS.md:52`), which can surprise a novice who didn't expect the machine to "start working" unattended.

12. **INSTALL.md never documents the network-mode prompt.** Setup asks a `4c/11 Choose your network mode` question (`setup.sh:1302-1325`), but INSTALL.md's step-by-step jumps from 4b (tier) to 5 (passphrase) (`INSTALL.md:193-207`), so a user reading along loses the map at exactly the airgapped/hybrid decision.
