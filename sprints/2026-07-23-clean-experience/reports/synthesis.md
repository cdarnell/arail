The three highest-stakes, most-repeated claims are confirmed in the actual source (hardcoded fabricated metrics at `researcher.py:1325-1331`, `docs` in the minimalist tier set at `app.py:124`, and unconsented live HuggingFace egress at `_builtin_buddy.py:948-951`). The reports are mutually consistent on the load-bearing findings. Synthesizing.

## Critique

ARAIL is, on inspection, two products wearing one skin. Underneath is a genuinely thoughtful local-first scaffold — a fail-closed knowledge gate that actually holds (`compiled_kb.py`), an honest planning-trace disclosure that teaches LLM-vs-heuristic reasoning (`researcher.py:1208-1246`), crash-resumable research runs, self-hosted fonts and a fully token-migrated design system, and airgapped-by-default egress enforcement that is load-bearing and correct. On top of that sits a marketing-grade surface that repeatedly promises more than the code delivers. The gap between those two layers is precisely where the owner "feels something is missing," and it is not a vague feeling — it is measurable across every dimension explored.

The owner's flagship desire — "intuitively build models" — is essentially unmet, and worse, it is actively obscured by five mutually-conflated "model" surfaces. The default "AI Engineer" is a two-line system-prompt wrap over `llama3.2:1b`. The `/build` tab, the only surface that says "Build, distill, and register models," is a thin HTTP client that hard-depends on a *separate* repo (`qukaizen-nucleus`) that ARAIL's own setup never installs or starts — so a fresh clone shows "nucleus down" and returns 502. The one genuine distillation pipeline (`scripts/build_ai_eng.sh`) is CLI-only, dormant behind placeholder HF repos, and never surfaced in the portal. `/tuning` is inference-throughput tuning, not weight training, yet sits one nav-click away with no explainer. And `docs/build-and-finetune-plan.md` (37KB) describes an entire model subsystem — `src/arail/models/`, `src/arail/jobs/`, `scripts/arail-model` — that does not exist on disk. A non-expert cannot possibly form a correct mental model of "how do I build a model here," because the platform itself does not have one.

The second structural problem is that the platform's core research and agent output is theater presented as substance — the single worst violation of "educate the user." The Researcher's "experiments" are timed `asyncio.sleep` loops (`researcher.py:923-965`); the analysis step asks the LLM to *invent* a metrics JSON, and with no model available emits the identical hardcoded constants `improvement_rate 0.15 / confidence_score 0.72 / data_points 24 / success=True` for every experiment (`researcher.py:1325-1331`, confirmed on disk). Those fabricated numbers are then written into the Knowledge Base and the "report" as if measured, with no "simulated" label anywhere, while the report itself never cites the sources the loop claims to gather. A platform whose stated purpose is to teach good AI research hygiene is instead teaching newcomers that research means watching a progress bar and trusting a confident, ungrounded report. This is corroborated independently by three separate reports.

The DaC/KB/agent-data-flow layer — which the owner calls "fundamental" — is the strongest part of the codebase and mostly honest: one human-gated write path, sha256 drift discipline, terms-as-data-never-prompted, world seals. But it is buttoned up only for Tier-1. The entire Tier-2 "user understanding" fact store — documented in detail across `docs/conversation-memory.md`, `docs/agents.md`, and ADR-0002 as if shipped — has *zero* implementation (no `recall_user_facts`, no `lab/pkb/understanding/`, no fact distillation). Meanwhile the "consent" story that should govern how agents reach data is decorative: the per-domain egress-consent flow is never consulted in hybrid mode, and Buddy silently puts the user's private goal text into a live HuggingFace URL query every ~15 minutes (`_builtin_buddy.py:948-951`, confirmed). The invariant a non-expert most needs to trust — "my agents only touch approved local knowledge and don't phone home" — is documented as true and is partly false.

On the owner's explicit boot-friction pain, the diagnosis is precise: the *shell* start path is clean, but the FastAPI startup event runs synchronous, boot-blocking work before the server accepts a connection — most damagingly a 60-second LLM subprocess (`parser.parse`, `app.py:888`) triggered by the shipped bootstrap goal, plus a LanceDB rebuild and a Neo4j connect with no skip flag. At runtime a model-registry health thread re-probes Ollama every 60s emitting "MODEL TIER DOWN" with *no off-switch*, and `/api/admin/components` shells out to `pip list` on every Admin load, ungated. There is no single "no auto-checks" master switch; silencing everything requires knowing ~7 env vars and three of the offenders have no gate at all. This is exactly the "too many times that has blocked me" experience, and it is fixable.

Finally, "inviting for friends and family" is undercut by disconnected, stale onboarding. The polished 3-step welcome wizard (passphrase → network → World) is *dead on the main path* because CLI setup captures a real passphrase and satisfies the gate, so most users never see the "what does your lab study?" moment. The dashboard's "read this first" banner points at a stale runbook (old min/max tiers, AirLLM 70B, a Qwen model that no longer matches reality). The single most important first action is labeled four different ways ("Run Research" / "Type a goal above" / "Open Autoresearch" / "Set Research Goal" / "Draft Swarm Plan"), and no "Run Research" button exists anywhere. And the *default* first goal a non-expert accepts by pressing Enter is "Optimize AirLLM's tokens-per-second when streaming a 70B Llama… sweep KV-cache quantization" — expert-hostile, and about a backend that isn't even installed.

The through-line: ARAIL has built the hard, honest primitives (gate, trace, airgap, resume) but wrapped them in aspirational copy, dead-on-arrival flows, and unlabeled simulation. The owner senses something missing because the platform *claims* to be an intuitive model-building playground while the model-building is in another repo, the research is fabricated, and the friendly wizard never runs. Buttoning up means making the surface tell the truth and closing the last mile on the primitives that already work.

## Open questions
- Model building: is the intended long-term path to bundle/auto-install `qukaizen-nucleus` so `/build` works out-of-the-box, or to make the CLI `build_ai_eng.sh` distillation the primary user-facing path? These imply very different UX investments.
- Simulated experiments: should the Researcher loop be made to run *real* small computations (a true minimal experiment engine), or is honest "illustrative/simulated" labeling on the existing narrative loop acceptable for the educational goal?
- Tiers: keep the two-tier (minimalist/maximus) split, or is the gating friction (Docs confusion, cosmetic-only enforcement, URL bypass) worth collapsing toward a single tier with feature toggles?
- Hybrid-mode egress: should agents (Buddy paper scans, Browser) be allowed *any* network reach in hybrid without a per-action user prompt, or should every egress require explicit consent even at the cost of convenience?
- Worlds: should mounting a World become a required step of first-run onboarding (so every lab has a subject), or remain optional to keep setup short?

## Master prompt ingredients
- Truth-in-UI is the prime directive: every surface must state what it actually does. No copy promising capabilities the code doesn't deliver (model building, git branches, fetched sources, shipped fact store).
- Label all simulated/model-generated/heuristic output as such — reuse the existing planning-trace provenance pattern for results and reports; never present invented metrics as measured, never default every experiment to success.
- One honest path per user goal: collapse the five conflated "model" surfaces into a single explained flow; pick one name per action and per surface and use it everywhere.
- Nothing probes or blocks unless the user invokes it: no synchronous LLM/rebuild/network work in the boot path; every auto-loop and version/package check behind a gate, with a single master off-switch and `doctor` as the explicit checkup surface. Preserve the airgap/egress guard exactly — it is load-bearing.
- The knowledge contract must be real and honest: human-gated approval before agents read anything (already true — keep it), no undisclosed egress, no private user text in third-party URLs, and docs that mark unbuilt subsystems as roadmap.
- Default to inviting for non-experts: friendly on-theme default goals, intent-aware seeded content, plain language over acronyms (no bare "DaC"), a first-run wizard that actually runs, and truthful model-footprint expectations.
- State where artifacts physically land — models, experiments, reports, conversations — in user-facing docs; honor "wipe PKB = wipe memory" with no override holes.
- Keep and finish the good primitives (fail-closed gate, planning trace, crash-resume, airgap, token'd design system); close the last mile rather than rebuild.
- Prune stale scaffolding: dead templates, deprecated aliases, stale sprint ledgers, and docs describing missing code erode trust and navigability.
- Verify claims against disk before asserting them — this codebase's docs and copy drift ahead of its implementation, so ground every change in what actually exists.
