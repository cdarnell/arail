## Summary
ARAIL has five easily-conflated "model" surfaces, and only one is automated. (1) The default `llama-ai-eng` persona is built by setup via `ollama pull llama3.2:1b && ollama create llama-ai-eng -f models/ai-eng/Modelfile.default` — a system-prompt wrap over a stock base, not real model building. (2) The `/build` tab orchestrator path (`POST /api/build/start`) and (3) its World-corpus path (`POST /api/build/world/start`) are thin HTTP clients that DEPEND on the separate qukaizen-nucleus repo's orchestrator/synthesizer/trainer running on localhost; ARAIL setup never installs or starts nucleus, so a fresh clone shows "nucleus down". (4) `scripts/build_ai_eng.sh`+`build_ai_eng.py` is a genuine download→fuse→bench→GGUF→ollama distillation-adjacent pipeline that is CLI-only, dormant (placeholder HF adapter repo + sha256), and never surfaced in the portal. (5) `/tuning` is inference-throughput tuning of a ≥1TB model (commits AeroLLM knob configs), NOT weight training. Artifacts scatter across Ollama's store, `lab/models/`, repo-root `build/`, `models/graduated/`, and the nucleus configs tree in a sibling repo, with no single user doc saying where a built model lands. `docs/build-and-finetune-plan.md` describes an entire model-management subsystem that does not exist on disk. The "Distill now" one-shot that would connect bake→seal→compact is only a VISION (sprints/2026-07-22-distill-now/ has a single VISION.md); compaction does not exist in `src/` at all.

For downloaded HF weights (GGUF/safetensors) used by AirLLM/aeroLLM streaming. git-ignored (`.gitignore:35`). BUT the in-repo `models/graduated/qkz-project-aware-2b-v1.0/adapters/adapters.safetensors` is a 1210-byte STUB (JSON metadata only: `{\"lora_weights\":{\"dtype\":\"F32\",\"shape\":[16,16]...}}`), not real weights. `superskill-spec.yaml` declares `location: models/graduated/...`, `shipping: git-lfs`, adapter_size_mb:15, but the real weights aren't in this clone.

6. NUCLEUS-SIDE TRAINED OUTPUT — the actual student model from /api/build/start or /world/start lands wherever the nucleus trainer writes it (entirely outside ARAIL's tree). ARAIL only re-imports it via `POST /api/models/register-artifact` using a `gguf_path` pulled from nucleus `graduation()` (`src/arail/portal/models_api.py:90-143`); the entry lands `not_installed` with an `ollama create` install hint, health flips once present.

7. `lab/data/build_jobs.json` — local build-job ledger (`src/arail/build/jobs.py:18-27`), keeping preflight snapshot, mode, red-override, phase.

THE FIVE BUILD/TUNE PATHS:

PATH C — /build tab World-corpus (`POST /api/build/world/start`, `build_api.py:211-290`; engine `build/world_corpus.py`). ## Gaps
1. Both intuitive /build paths hard-depend on the SEPARATE qukaizen-nucleus repo running locally (orchestrator :8000, synthesizer :8005, trainer :8006 — src/arail/build/nucleus_client.py:35-44). ARAIL setup.sh never installs or starts nucleus (it's a NATS+orchestrator+certifier+trainer docker-compose stack per sprints/2026-07-22-distill-now/VISION.md:121-125), and README/INSTALL never tell a user to. So on a fresh clone the /build tab connectivity strip (build.html:95-98) shows 'nucleus down' and POST /api/build/start returns 502 (build_api.py:163-169). This is the single biggest blocker to 'intuitively build a model'.
2. The user-facing World-corpus path emits NO cryptographic seal — build_api.py:377-381 returns seal:None for world_corpus mode, and the certifier/Ed25519 'Knowledge Isotope' seal only exists on the orchestrator path the World path deliberately skips (world_corpus.py:1-15). So the easy path can train but cannot prove/verify what it produced.
3. Compaction ('knowledge becomes memory') does not exist at all: grep for bake/compact in src/arail finds only unrelated hits; sprints/2026-07-22-distill-now/VISION.md:48 confirms 'no pointer-swap, no archive/<bake-id>/, no corpus_sha256 addressing, no receipt, no rollback'. The refresh-loop RETAIN(bake+compact) stage is paper.
4. The 'Distill now' one-shot that would wire bake→seal→smoke→compact is only a VISION — sprints/2026-07-22-distill-now/ contains ONLY VISION.md (no ARCHITECTURE/BUILD_LOG/REVIEW/TEST_REPORT), so nothing is built. No 'Distill now' button exists on /build or /dac.
5. NucleusClient.train_direct 'just launches a background task and returns immediately' (nucleus_client.py:167-180) with no guarantee that polling converges to a model file ARAIL chat can load; re-importing requires a gguf_path from nucleus graduation via /api/models/register-artifact (models_api.py:100-129). The loadable-artifact-back-in-ARAIL link is unproven (VISION disconfirmer 2, lines 126-130).
6. docs/build-and-finetune-plan.md (linked from README-adjacent docs and CERTIFIED_MODELS) describes a whole model subsystem that DOES NOT EXIST: src/arail/models/{manifest,download,fit}.py, src/arail/jobs/orchestrator.py, scripts/arail-model, deploy/docker/Dockerfile.finetune-worker, src/arail/models/adapters/base.py — all verified missing (src/arail/models/ and src/arail/jobs/ directories are absent). A user following this doc hits nothing real.
7. The in-repo 'graduated' model is a stub: models/graduated/qkz-project-aware-2b-v1.0/adapters/adapters.safetensors is 1210 bytes of metadata only (no real tensors), despite superskill-spec.yaml claiming a 15MB LFS-shipped adapter. Registry note (store.py:~245) says 'Adapters-only today: fuse the LoRA and register it via the Model Building tab to activate' — but no fuse UI exists and qkz-project-aware-2b is dormant (Modelfile.gemma is a __PLACEHOLDER__).
8. No single user-facing doc states where a built model lands. Artifact locations are split across Ollama store, lab/models/ (config.py:79), repo build/ (build_ai_eng.sh:171), models/graduated/, nucleus configs tree (manifest.py:27-31), and nucleus-side output — mentioned only in CLAUDE.md:134 (dev-facing) and scattered app.py reveal endpoints.
9. The genuine distillation-adjacent pipeline (scripts/build_ai_eng.sh) is CLI-only, never surfaced in the portal, and dormant: ADAPTER_REPO 'qukaizen/qkz-opus4.7-aieng-1b-v2.1-adapter' + ai_eng_sha256 are placeholders (setup.sh:893-897), Modelfile.production points at unpublished qukaizen/ai-eng:1.5b, and check_ai_eng_artifact.sh always exits 1 until an artifact is uploaded. A non-expert can never discover it.
10. Simulation is pervasive and can be mistaken for real output: /build dry_run mode is badged SIMULATED (build_api.py:88-92), all preflight numbers are heuristic estimates (preflight.py:248-250), model_specs.py benchmarks are 'illustrative community snapshots' (model_specs.py:16-21), and build_ai_eng.py dry-run writes literal b'STUB_GGUF' (build_ai_eng.py:518). Anthropix cost/time on the build cards is an estimate, not a quote.
11. Tier2 'extra reasoning depth' on the World build cannot be automated: it needs a manual restart of the nucleus teacher process with TEACHER_BACKEND=anthropic between passes (world_corpus.py:270-275) — the UI just tells the user to read the build log for instructions (build.html:170-174), which breaks the one-click promise.
12. The /build tab, /tuning tab, build_ai_eng.sh, and the Ollama persona-wrap are four unrelated notions of 'model' with no unifying explainer, so a non-expert cannot tell that /tuning tunes inference speed (not weights), that /build needs a second repo, and that the default 'AI Engineer' is just a prompt over llama3.2:1b.
