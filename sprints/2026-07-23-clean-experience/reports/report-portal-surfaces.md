## Summary
The ARAIL portal is a large, feature-rich FastAPI surface that is mostly polished on its primary tabs (Chat, Dashboard, Autoresearch, DaC/Knowledge, Admin) and carries a well-executed design-system v2 rollout: every page template now extends `base.html`, per-surface CSS files contain zero hardcoded hex colors (all CSS-variable/token driven), and fonts are self-hosted for airgap. The dominant structural liability is `src/arail/portal/app.py` at 11,587 lines holding ~180 routes — a monolith that only partially extracted concerns into sibling modules (`build_api`, `models_api`, `chat_sessions_api`, `wiki_routes`, `world_routes`, `librarian_routes`, `openai_compat`). The most user-visible rough edges are the Agents → Activity tab ("coming soon"), an unconfigured maximus deep-model (`__TODO_DEEP_MODEL__`), and a naming divergence where the docs/README "Knowledge Base" surface is labeled the jargon acronym "DaC" in the live nav. Tier-gating is cosmetic (nav-link hiding only) — maximus page routes render for minimalist users who type the URL directly. A dead template (`teacher.html`, 417 lines), stale sprint ledgers, and legacy `/api/pkm/*` alias duplicates round out the debt.

## Gaps
1. **`app.py` is an 11,587-line, ~180-route monolith.** Route extraction was started (`build_api`, `models_api`, `wiki_routes`, `world_routes`, `openai_compat` registered at `app.py:587-604,1156`) but the bulk (chat, pkb, admin, system, tuning, teacher, research, worlds) stays inline. High-friction to navigate/modify.
2. **Agents → Activity is a user-facing "coming soon" stub.** The Activity tab button renders unconditionally (`agents.html:30`) and its panel shows only `"Agent activity feed coming soon. For now, see agent cards in the Status view."` (`agents.html:413-414`). A first-time user clicking the tab hits a dead end.
3. **Maximus deep-model is unconfigured (`__TODO_DEEP_MODEL__`).** `app.py:7032` sets AirLLM `default_model = "__TODO_DEEP_MODEL__"`, consumed at `:7275,7278,7651,11056`; deep mode shows a "configure your deep model" notice instead of working. The maximus "deep" value proposition is half-shipped in the portal.
4. **"Knowledge Base" vs "DaC" naming divergence + jargon.** README (`README.md:67,217`) and CLAUDE.md (`:53`) call the fifth surface "Knowledge Base" at `/knowledge`; the live nav labels it "DaC" (`_nav.html:48-50`) and `/knowledge` 307-redirects to `/dac` (`app.py:9756-9760`). "DaC" (Declarative-as-Code) is an unexplained acronym — directly at odds with the stated goal of being inviting for non-expert friends/family.
5. **Docs tier claim contradicts code.** CLAUDE.md:120 states "`max` adds Admin and Docs," but `_TIER_SURFACES` puts `docs` in minimalist (`app.py:124`) and the nav shows Docs to minimalist users (`_nav.html:62-65`). Doc/code drift that misrepresents the tier boundary.
6. **Tier-gating is cosmetic (nav-only), no server-side enforcement.** Page routes `/build` (`app.py:9763`), `/admin` (`:4126`), `/tuning` (`:11053`), `/notebooks` (`:2143`), `/terminal` (`:1822`), `/plugins` (`:2277`) render their templates with no tier guard. A minimalist user who types the URL gets the full maximus page. The gating is a nav illusion, not a boundary.
7. **Orphaned template `teacher.html` (417 lines).** `/teacher` 307-redirects to `/chat` (`app.py:11444-11446`) and no `TemplateResponse` renders `teacher.html` — the only reference is a code comment (`app.py:11436`). Dead code; the `/api/teacher/*` endpoints (`:11474,11499,11534`) also linger.
8. **Docs "Ask Buddy" seed handoff is an admitted stub.** `doc_viewer.html:287`: `"Sprint 3 TODO: wire chat-side seed consumption (/chat?seed= is a stub in Sprint 2)."` The CTA renders but the chat side never consumes the seed.
9. **Legacy `/api/pkm/*` duplicates `/api/pkb/*`.** Five aliases (`app.py:10995-11019`) marked "deprecated, kept for one release" still ship — dead surface area/confusion for anyone reading the route list.
10. **Overlapping proposal panels on the DaC page.** `dac.html` loads `librarian-panel.js`, `dac-proposals.js`, and `compiled-kb.js` (`:70-74`) rendering three separate approval/proposal panels (`:45-50`) plus the Librarian section — overlapping "term/KB review" concepts a first-time user must disambiguate.
11. **Knowledge Canvas integration ships inactive.** `core/knowledge-canvas/` has only TSX/Vite source (no `dist/`), so `/integrations/knowledge-canvas` always redirects to `/wiki/graph` (`app.py:2091-2092`). The embedded-canvas feature is effectively unreachable out of the box (degrades gracefully, but the advertised surface never appears).
12. **Stale sprint ledger for the design-v2 rollout.** `SPRINT.md` still marks build A "pending" and ship "in progress," and `BUILD_LOG.md` marks base.html migration "(in progress)" / Phase B "(running)," yet all page templates already extend `base.html` and CSS is fully tokenized. The record no longer matches shipped state.
13. **Mixed/stale sprint references in docs registry.** `docs_registry.py:67` calls INDEX.md a "legacy hub placeholder; Sprint 2 will replace," while `app.py:2318` says INDEX.md "was deleted in Sprint 3" — two inconsistent sprint claims about the same artifact.
14. **`mission.html` is a thin duplicate of the dashboard.** `/mission` renders the same `current_goal`/`research_status`/`recent_activity`/`lab_theme` context as `/` (`app.py:1341-1351`), linked as "Curated view →" (`dashboard.html:569`) — a near-duplicate surface with unclear distinct value.
15. **Internal naming drift across the Autoresearch/Workbench tabs.** Nav label "Autoresearch" → route `/autoresearch` → template `research.html` → `active='research'` → `research.css`; nav "Workbench" → route `/notebooks` → CLAUDE.md "Notebooks." Four different names for two surfaces makes the codebase harder to grep and reason about.
