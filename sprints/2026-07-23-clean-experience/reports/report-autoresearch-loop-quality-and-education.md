## Summary

The `/autoresearch` (a.k.a. `/research`) surface is driven by the **Researcher agent** (`src/arail/agents/researcher.py`), which is a *different engine* from the `/tuning` inference-tuning loop (`src/arail/experiments/autoresearch.py`). It has a genuinely well-built control skeleton — honest planning-trace disclosure, transparent LLM-vs-heuristic labeling, robust crash/resume via `run_state.json`, and clean airgap gating — but its scientific core is hollow: the "experiments" measure nothing. Step 4 of the loop just sleeps for `LAB_EXP_RUNTIME_SEC` (default 60s) per experiment while the LLM narrates plausible-sounding "observations," and the analysis step asks the LLM to *invent* a metrics JSON (or, with no model, emits the hardcoded constants `improvement_rate 0.15 / confidence_score 0.72 / data_points 24 / success=True` for every experiment). Those fabricated numbers are then written into the PKB as if they were real measurements, and the final "report" is unsourced model prose that never cites the sources the loop claims to gather. Compounding the confusion, the page's headline copy and "Experiment Branches" panel promise git-branch artifacts that only the *other* (`/tuning`) loop produces — the Run button here creates none — and the one "How the loop works" learn-link points at a non-existent doc anchor. For a non-expert "exploring the powers of AI," the surface teaches that research = watch a progress bar, then trust a confident report built on nothing.

## Current state

**Goal capture & planning.** `POST /api/goal` (`app.py:2733-2755`) parses free text via `GoalParser` (`skills/goal_parser/__init__.py:79-126`, subprocess-isolated LLM with heuristic fallback `parse_offline` at `:187-231`), persists via `GoalStore.set_goal` (`goals.py:64-102`), then auto-starts the Researcher and fire-and-forgets `_auto_draft_program` (`app.py:2855-2902`). Swarm goals go through a preview/confirm flow (`app.py:2765-2852`) using a fully **templated** planner (`swarm_goals.py:245-286`; static `_BASE_WORKERS`/`_ARCHETYPE_WORKERS` catalogs at `:32-53`, keyword archetype detection, no LLM).

**Planning trace (the best educational feature).** `_plan_research` (`researcher.py:1103-1206`) widens the LLM pool to 5-8 hypotheses, runs the top `_CHOSEN_LIMIT=5`, and records chosen/alternatives/source/rationale/raw-LLM-response into `_planning_trace` (`:1208-1246`). Surfaced honestly at `GET /api/research/planning-trace` (`app.py:3671-3697`) and rendered as "Why these hypotheses?" with an LLM-vs-heuristic badge (`research.html:154-173`, JS `:886-960`).

**Run lifecycle.** `start/pause/resume/stop` (`researcher.py:435-492`) and `_run` (`:692-1062`) drive six steps (plan → design → gather sources → run → analyze → report). Endpoints `app.py:3594-3668`. Pause/halt are cooperatively honored in <1s granules (`:946-958`, `_wait_if_paused` `:1064-1070`). Swarm "worker lanes" are **cosmetic** — `_set_swarm_lane_status`/`_sync_swarm_phase` (`:607-676`) only write status strings to `swarm-<id>` pseudo-agents for the Agents tab; no per-worker execution occurs.

**The experiments are simulated, not measured.**
- Step 4 (`researcher.py:923-965`) is a timed sleep emitting `_generate_observation` output — the LLM writing "a single concise observation from initial data collection" (`:1274-1291`); heuristic fallback is the canned "shows promising patterns. Baseline metrics established."
- Step 5 `_analyze_experiment` (`:1293-1331`) asks the LLM to produce `improvement_rate/confidence_score/data_points/conclusion/success` — pure fabrication — and with no model returns the fixed `{0.15, 0.72, 24, "supports the hypothesis with moderate confidence", success=True}` (`:1325-1331`). Every experiment therefore "succeeds" identically offline.
- `_generate_report` (`:1381-1445`) is LLM prose (prompt at `:1396-1404` includes only hypothesis text — **not** the observations, the metrics, or any source) or a template; neither cites sources.

**Program/source machinery belongs to the OTHER loop.** `program_drafter.py` writes `lab/pkb/research/program.md` + `train.py` on goal-set (`:99-196`); `program_loader.py:51-102` and `train_template.py` are consumed by `experiments/autoresearch.py` (the `/tuning` loop), per their own docstrings (`program_loader.py:1-11`). The Researcher agent never reads `program.md`, runs `prepare.py`, or applies `train.py`. `default_sources.yaml` is 6 links all about "running LLMs on laptop hardware" (AirLLM/GGUF/llama.cpp/vLLM) — pinned into every lab's program.md under "Curated defaults — 'LLMs on disk'" (`program_drafter.py:408-414`) regardless of intent.

**Sources are proposed but never fetched or cited.** Step 3 (`researcher.py:887-921`) calls `curator.propose_sources` + `submit_proposals` (consent requests only); `fetch_approved` (`curator.py:129-149`) is never invoked in the loop, and nothing from curated/KB sources reaches the report.

**Airgap behavior (correct).** `is_airgapped()` → `propose_sources` returns `[]` (`curator.py:91-93`); `fetch_approved` hard-blocks (`:133-134`); drafter live-fetch needs hybrid + `ARAIL_AUTORESEARCH_FETCH_EXTRAS=1` and is a stub returning `[]` anyway (`program_drafter.py:201-206, 261-266`). Airgapped runs are fully local — but grounding then reduces to the (AI-only) curated YAML + KB hits.

**Artifacts land in two trees.** Experiments: `lab/data/experiments/<id>.json` (`experiment_tracker.py:156-157`, `config.py:82`) — **outside** the PKB (so not covered by "wipe PKB = wipe memory"). Report → `lab/pkb/agents/research/<date>_<goal>_report.md` (`pkb.py:677-690`); per-experiment markdown → `agents/experiments/` (`:693-706`); `_rollup.md` reprints the fabricated metrics as fact (`:736-747`); recommendation is a near-empty stub pointing back at the report (`researcher.py:1017-1021`, `pkb.py:775-793`). Report also mirrored to `lab/data/goals/current.json` (`goals.py:202-207`).

**Crash/resume (solid).** `run_state.json` persisted every transition (`goals.py:26-54`, `researcher.py:517-542`); boot reconciliation auto-resumes or marks interrupted (`app.py:3540-3591`); honest checkpoint semantics — <0.3 re-plans, ≥0.3 reloads experiments from the tracker (`researcher.py:692-718, 877-885`) and skips completed ones (`:935-938`).

**No-model / empty-KB path.** No usable model → `_get_router` returns None (`researcher.py:165-177`); the whole loop still "completes," writing generic heuristic hypotheses (`:1189-1192`), the fixed fake metrics, and a template report to the KB, with nothing flagging the run as content-free. Empty KB emits "No KB entries match… proceeding from prior knowledge" (`:782-787`) and proceeds.

## Gaps

1. **Experiments measure nothing; the loop is theater.** Step 4 is a sleep + LLM narration (`researcher.py:923-965`, `:1274-1291`). No dataset, no metric, no computation. A non-expert watching the progress bar and step dots is led to believe real experimentation occurred.
2. **Fabricated metrics are presented as measured data.** `_analyze_experiment` hallucinates `improvement_rate/confidence_score/data_points` (`researcher.py:1293-1322`), and with no model emits identical hardcoded constants with `success=True` for *every* experiment (`:1325-1331`). These flow verbatim into `agents/experiments/*.md` and `_rollup.md` (`pkb.py:736-747`) as trustworthy findings. This is the single biggest trust/education defect.
3. **The report is unsourced model assertion.** `_generate_report` (`researcher.py:1381-1445`) never receives the observations, the metrics, or the gathered sources; sources are proposed but never fetched (`curator.fetch_approved` unused) and never cited. Output looks authoritative but is ungrounded — the opposite of teaching good research hygiene.
4. **Two different loops conflated on one page.** The headline "Every experiment is a git branch… the experiment ledger" (`research.html:13-14`), the empty-state promise "Every winning variant becomes a branch — `autoresearch/<id>` — committed to your repo" (`:274-276`), and the "Experiment Branches / autoresearch/* git history" panel (`:238-263` → `/api/experiments/branches`, `app.py:3957`) all describe `/tuning` (`experiments/autoresearch.py`). The Run button on this page drives the Researcher, which creates **no branches** — so a newcomer runs the loop, sees experiment cards, and finds the Branches panel empty/irrelevant.
5. **Broken primary educational link.** `research.html:271-272` links to `/docs/agents-explained.md#the-research-loop`; that anchor does not exist (no such heading in `docs/agents-explained.md`, headings enumerated at `:16-366`), and the doc doesn't explain the research loop at all. The sole "How the loop works" affordance for a beginner dead-ends.
6. **No-model runs silently produce confident-but-empty artifacts.** With no usable model the loop completes end-to-end (`researcher.py:1189-1192, 1325-1331, 1409-1445`) and writes a report + fake metrics to the KB, with no run-level banner telling the user the output is content-free. This actively misleads the target "no expert" audience.
7. **Curated sources are AI-only, injected into every lab.** `default_sources.yaml` (AirLLM/GGUF/vLLM…) is pinned into program.md under "Curated defaults — 'LLMs on disk'" (`program_drafter.py:408-414`) even for farming/culinary/health/trade intents — off-topic noise that undercuts the "inviting for non-experts" goal.
8. **Experiment store lives outside the PKB contract.** Experiment JSON is under `lab/data/experiments/` (`config.py:82`), not the PKB, so "wipe PKB = wipe memory" leaves experiment records behind; and a wiped `EXPERIMENTS_DIR` with a surviving goal makes `_reload_experiments` silently skip missing files (`researcher.py:688-689`), so a ≥0.3 resume can regenerate a report from zero reloaded experiments.

## Quick wins

- Fix the dead learn-link: add a "## The research loop" section (with the `#the-research-loop` anchor) to `docs/agents-explained.md`, or repoint `research.html:271-272` to an existing doc; this is the one on-ramp a beginner is told to click.
- Stop presenting fabricated numbers as measured: when the analysis used the heuristic fallback (or the LLM invented the JSON), label the metrics "illustrative" in the UI and in `_experiment_markdown`/`_rollup` (`researcher.py:1333-1379`, `pkb.py:736-747`), and don't default `success=True` for every experiment (`:1331`).
- Reuse the honest planning-trace pattern (`researcher.py:1208-1246`) for the run/analyze/report steps — surface "this run had no model; results are placeholders" whenever `_router` is None, so no-model runs are unmistakable.
- Decouple the two loops on the page: either gate the "git branch" headline + Experiment Branches panel (`research.html:10-17, 238-263, 274-276`) behind an actual `/tuning` run, or relabel them so the Researcher's real artifacts (`lab/pkb/agents/research/…`) are what the copy points to.
- Feed the loop's own observations + gathered/curated sources into `_generate_report`'s prompt (`researcher.py:1396-1404`) so the report cites something, and actually call `curator.fetch_approved` (or drop the "gathering sources" step's claims).
- Make the curated defaults intent-aware: skip the "LLMs on disk" block in `program_drafter.py:408-414` for non-AI intents, or key `default_sources.yaml` by domain.
